# Отчёт: Scaled Dot-Product Attention на CPU и CUDA

## 1. Цель

Реализовано выражение:

`Attention(Q,K,V) = softmax((Q*K^T)/sqrt(d))*V`

Для обязательного теста используются `N=512`, `d=64` и детерминированные
матрицы Q, K, V с seed 2026. CPU и обе CUDA-версии получают одни и те же данные.

## 2. CPU-эталон

`attention_cpu.cpp` содержит прямые вложенные циклы C++ без OpenMP, SIMD API,
CUDA или ответа GPU. Это намеренно наивная последовательная реализация,
требуемая заданием. Она служит независимым эталоном правильности. Компьютер
имеет Intel Core i9-14900K, 24 физических и 32 логических процессора, но
эталонный алгоритм выполняется одним CPU-потоком.

## 3. Базовая CUDA-реализация

1. `qk_matmul_basic`: двумерный grid; один CUDA thread вычисляет один элемент
   матрицы `Q*K^T`.
2. `scale_scores`: один thread умножает один score на `1/sqrt(d)`.
3. `row_softmax`: один block из 256 threads обрабатывает строку. Две редукции
   в shared memory находят максимум и сумму. Перед `exp` вычитается максимум.
4. `attention_v_basic`: двумерный grid; один thread вычисляет один элемент
   итоговой матрицы `P*V`.

Матрицы размером `N*d` и `N*N` размещаются через `cudaMalloc`. Q/K/V
копируются Host-to-Device, результат копируется Device-to-Host. Все потенциально
выходящие за логические размеры threads имеют boundary checks.

## 4. Оптимизированная CUDA-реализация

`qk_matmul_tiled_scaled` и `attention_v_tiled` используют blocks `16x16`.
Каждый block загружает плитки входных матриц в `__shared__` memory и повторно
использует данные 16 раз. Scaling объединён с записью результата QK. Это
уменьшает обращения к global memory и число запусков kernels. Между фазами
плитки используются `__syncthreads()`.

## 5. Правильность

После CUDA-вычисления каждый выходной элемент сравнивается с CPU. Допуск:
`max_abs_error <= 2e-4`. При превышении программа возвращает код 2.

Проверенный результат RTX 4060:

| Реализация | Max abs error | Mean abs error | Статус |
|---|---:|---:|---|
| CUDA basic | 4.47035e-08 | 5.48305e-09 | PASS |
| CUDA optimized | 4.47035e-08 | 5.48305e-09 | PASS |

## 6. Методика измерений

- Оборудование: Intel Core i9-14900K и NVIDIA GeForce RTX 4060 8 GB.
- CUDA Toolkit/NVCC 13.2; compute capability 8.9; 24 SM.
- Пять одинаковых прогревочных итераций исключаются.
- Затем выполняются 50 измеряемых итераций каждого варианта.
- CPU и CUDA получают одинаковые Q/K/V.
- `kernel_ms` измеряется CUDA Events.
- `end_to_end_ms` включает H2D, kernels, синхронизацию и D2H.
- CPU-время включает создание временных vectors `scores/output` внутри каждого
  вызова наивного эталона. CUDA device-буферы выделяются один раз до warm-up,
  поэтому CUDA-цифра описывает прогретый повторно используемый worker.
- Запуск процесса, создание CUDA context и first-use initialization не входят
  в таблицу; это сравнение steady-state throughput, а не cold start.

## 7. Результаты Attention

| Реализация | Kernel, ms | End-to-end, ms | Ускорение к CPU |
|---|---:|---:|---:|
| CPU naive | - | 10.6346 | 1.00x |
| CUDA basic | 0.251794 | 0.350112 | 30.37x |
| CUDA optimized | 0.114701 | 0.211658 | 50.24x |

Эти результаты одновременно показывают корректность и эффект параллелизма.
Оптимизированная CUDA-версия быстрее базовой примерно в 1.59 раза по полному
времени за счёт shared-memory tiling и объединения scaling.

## 8. Узкие места

- Два матричных умножения имеют порядок `N^2*d`.
- Матрица scores содержит `N^2` значений и создаёт большой поток global memory.
- Softmax требует зависимых редукций и синхронизации внутри каждой строки.
- Для маленьких N расходы запуска kernels и PCIe-копирования уменьшают выигрыш.
- Выбор tile/block ограничивается регистрами, shared memory и occupancy.
- CPU-эталон последовательный; сравнение с многопоточной CPU-библиотекой было
  бы отдельным экспериментом и не заменяет требуемый naive CPU baseline.

## 9. Дополнительная демонстрация распознавания лиц

Она не заменяет Attention, но показывает параллельную обработку реальной
нейросетью. Использован фиксированный manifest из 50 файлов; порядок CPU/CUDA
чередуется между прогонами, повторные изображения не кэшируются и не
пропускаются.

| Эксперимент | CPU median | CUDA median | Ускорение | Agreement |
|---|---:|---:|---:|---:|
| 50 попыток, 10 прогонов | 1137.15 ms | 555.59 ms | 2.05x | 100% |
| 500 попыток, 5 прогонов | 8168.78 ms | 3184.44 ms | 2.57x | 100% |

В 500-попыточном эксперименте 50 фиксированных файлов обрабатываются по 10
раз. API подтверждает `physical_attempt_count=500` в каждом прогоне. CSV,
manifest и полные статистики находятся в `results/face-pipeline*`.

## 10. Воспроизводимость

`verify_cuda_assignment.bat` выполняет строгую сборку NVCC и обязательную
проверку. Если CUDA недоступна, сборка или точность нарушена, команда завершается
ошибкой. Успешный результат создаёт `results/rtx4060-n512-d64.csv`.

HOW THE DETECTOR WORKS

What happens to the image inside the neural network

This inspector shows the detector-only CUDA module: one-time initialization, DeepID inference, reference comparison, and the final identity result. Hive and web-interface code are outside this source listing.

CUDA SOURCE VARIANT

Choose the recognition path to inspect

01

Initialization and device selection

Imports the detector dependencies, defines identity thresholds, initializes caches, and verifies whether the requested mode can use CUDA.

Open scheme
02

Weights and DeepID model

Reads the trained binary tensors, builds the exact DeepID forward pass, moves its buffers to CPU or CUDA, and caches the model.

Open scheme
03

Screenshot variants and input tensors

Converts the screenshot to RGB, creates full-frame and center-crop variants, resizes them to 47 × 55, normalizes pixels, and produces channel-first tensors.

Open scheme
04

One-time reference initialization

Finds the known-person images, removes duplicate paths, embeds every reference in one model batch, and caches the normalized reference matrix.

Open scheme
05

Embedding comparison and identity decision

Embeds the prepared variants together, compares them with cached references, keeps each person’s best score, and applies score and margin thresholds.

Open scheme
06

Single-image execution and result

Runs the complete path for one screenshot, measures completed inference time, and returns the selected identity, scores, device, and acceptance flag.

Open scheme

GPU and CPU mode

GPU mode runs the heavy vector and image operations through the accelerator path. CPU mode runs the same recognition logic on the processor. The expected identity result should stay the same; the difference is mainly where the computation runs and how long it takes.
